The module centers on a single Eloquent `Vendor` model (`app/Models/Vendor.php`) backed by the `vendors` migration (`database/migrations/2026_11_26_000002_create_vendors_table.php`), which declares fields `code`, `name`, `contact_name`, `phone`, `email`, `address`, `npwp`, `note`, `is_active`. A second migration (`2026_11_26_000003_add_vendor_id_to_inventory_movements_table.php`) adds the foreign key that lets `Vendor::inventoryMovements()` (a `HasMany`) count related transactions. Filament integration lives under `app/Filament/Resources/Vendors/`: `VendorResource.php` is the entry point declaring `$model`, navigation metadata, `form()`, `table()`, and `getPages()` routing to three custom page classes in `Pages/` (`ListVendors`, `CreateVendor`, `EditVendor`). The resource hides the delete action when a vendor has any linked inventory movement, enforcing referential integrity at the UI layer. Test coverage is provided by `tests/Feature/VendorResourceTest.php`, and `Database\Factories\VendorFactory` seeds realistic vendor fixtures via Faker.
