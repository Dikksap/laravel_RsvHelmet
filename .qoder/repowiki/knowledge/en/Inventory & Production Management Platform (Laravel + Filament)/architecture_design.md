Standard Laravel layering: `app/Models` define the domain entities (Item, InventoryBalance, ProductionBatch, StockOpname, ItemRequest, Vendor, etc.), `app/Services` encapsulate cross-model business logic (BomExplosionService, BatchProgressService, StockMovementService, ExternalBarangSyncService), and `app/Filament/Resources/*` provide CRUD UIs that delegate to those services. A single Filament Admin Panel is registered via `App\Providers\Filament\AdminPanelProvider`, which wires all Resources, Pages, Widgets, Imports/Exports, and custom Form Components (`InfiniteSelect`). Cross-cutting concerns (auth customization, queue/mail/cache/filesystem) are configured in `config/` and bootstrapped through `bootstrap/providers.php`. The database schema lives in `database/migrations` with one migration per table, seeded by `DatabaseSeeder` plus domain seeders (`MasterDataSeeder`, `FinishGoodItemSeeder`, `MasterItemSeeder`). Public-facing flows (item request form, PDF generation) use Livewire and Blade views under `resources/views`, while the rest of the app is Filament-driven.
