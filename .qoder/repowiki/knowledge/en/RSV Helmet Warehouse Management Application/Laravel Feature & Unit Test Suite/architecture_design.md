Tests follow Laravel's standard `tests/` layout with two layers: `Feature/` for integration tests that boot the full application (HTTP requests, Livewire/Filament components) and `Unit/` for isolated unit tests. `TestCase.php` is the shared base extending `Illuminate\Foundation\Testing\TestCase`. Feature tests use the `RefreshDatabase` trait to reset state per test and authenticate in `setUp()` via `$this->actingAs(User::factory()->create())`. Tests target three surfaces: (1) Livewire/Filament components through `Livewire::test(Component::class)` with chained assertions like `assertCanSeeTableRecords`, `callTableAction`, `assertHasNoErrors`; (2) HTTP endpoints via `$this->get('/admin/...')->assertOk()->assertSee(...)`; (3) Service-layer classes such as `ExternalBarangApiService` using `Http::fake([...])` keyed by URL glob patterns to stub external calls. Domain fixtures are created exclusively through model factories (`Item::factory()`, `ProductionBatch::factory()`, `InventoryMovement::factory()`, etc.).
