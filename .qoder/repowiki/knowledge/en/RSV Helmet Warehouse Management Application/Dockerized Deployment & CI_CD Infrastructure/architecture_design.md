Two-tier container setup: a development compose (`docker-compose.yml`) builds from `Dockerfile` (PHP 8.4-cli + artisan serve) with host-volume binding and a MariaDB 11 companion; a production compose (`docker-compose.prod.yml`) runs prebuilt images on port 8001:80 over an isolated bridge network `rsv_network` with persistent volumes `db_data`, `app_storage`, `app_logs`. The production image (`Dockerfile.prod`) uses three Docker stages — Composer builder, Node 22 Vite frontend builder (with Filament vendor CSS/views), and a PHP 8.4-FPM Alpine runtime hosting Nginx, PHP-FPM, and a queue worker under Supervisor. Runtime boot is orchestrated by `docker/production/entrypoint.sh`, which creates storage dirs, fixes permissions, optionally waits for MySQL and runs migrations, then caches config/routes/views before exec-ing Supervisor. Supervisor (`supervisord.conf`) manages three processes: php-fpm (priority 10), nginx (priority 20), and a single `queue:work` worker (priority 30). Nginx proxies PHP via FastCGI on 127.0.0.1:9000, serves static assets with 1-year cache, and applies security headers. CI/CD (`.github/workflows/ci-cd.yml`) runs in three jobs on push to `master`: `test` (Pint + PHPUnit against in-memory SQLite), `build-and-push` (Buildx multi-stage build of `Dockerfile.prod` tagged `latest` + short SHA + git tag, pushed to `ghcr.io/dikksap/laravel_rsvhelmet`), and optional `deploy` via SSH that pulls the image and runs `config:cache`, `route:cache`, `view:cache`. Environment variables are parameterized through `${VAR:-default}` / `${VAR:?error}` patterns across both compose files.
