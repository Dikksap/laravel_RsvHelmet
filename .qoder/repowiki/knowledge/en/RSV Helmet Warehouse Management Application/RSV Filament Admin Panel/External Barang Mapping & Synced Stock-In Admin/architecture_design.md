Two sibling Filament `Resource` classes under `app/Filament/Resources/`, each with a `Pages/` sub-namespace holding custom list/create/edit pages registered via `getPages()` returning explicit route maps.

- `ExternalItemMappingResource` (CRUD) manages `App\Models\ExternalItemMapping`. Its form is split into two `Section`s: an external-variant section driven by `App\Services\ExternalBarangApiService::fetchAvailableVariants()` populating a live `Select` that auto-fills variant fields, and an internal-mapping section using a custom `App\Filament\Forms\Components\InfiniteSelect` for paginated lookup of active `Item`s. The table counts related `syncedBarangs` and exposes edit/delete actions plus bulk delete.
- `ExternalSyncedBarangResource` is read-only: empty `form()`, no actions/bulkActions, and a table showing relation columns (`item.item_name`, `mapping.external_variant_code`, `warehouse.name`, `productionBatch.batch_code`, `movement.id`) with a status badge derived from the external API state string.
- Both resources register themselves in the `Integrasi Eksternal` navigation group via static `$navigationGroup` / `$navigationIcon` / `$navigationSort` properties.
- The list page for mappings (`ListExternalItemMappings`) adds two header actions: `tarik_varian` performs name-based auto-matching against active `Item`s and creates mappings, while `sinkron_stok` opens a modal form delegating to `App\Services\ExternalBarangSyncService::sync(...)` with warehouse, limit, pagination, and dry-run options.
