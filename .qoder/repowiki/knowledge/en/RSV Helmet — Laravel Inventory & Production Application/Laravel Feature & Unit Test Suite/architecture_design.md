Tests follow Laravel's standard `tests/` layout with two layers: `Feature/` for integration tests that boot the full application (HTTP requests, Livewire components, Filament pages) and `Unit/` for isolated unit tests. `TestCase.php` is the shared base extending `Illuminate\Foundation\Testing\TestCase`, providing a common entry point. Feature tests use `RefreshDatabase` to reset state per test and `actingAs(User::factory()->create())` in `setUp()` to authenticate as a random user. Tests target three kinds of application surfaces: (1) Livewire/Filament components via `Livewire::test(Component::class)` with chained assertions like `assertCanSeeTableRecords`, `callTableAction`, `assertHasNoErrors`; (2) HTTP endpoints via `$this->get('/admin/...')->assertOk()->assertSee(...)`; (3) Service-layer classes (e.g. `ExternalBarangApiService`) using `Http::fake([...])` to stub external HTTP calls. Factories (`Item::factory()`, `ProductionBatch::factory()`, etc.) are used throughout to seed domain data.
